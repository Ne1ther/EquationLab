# 源码构建与交付要求

源码仓库面向开发者，完整PKG面向普通用户。源码构建需要开发工具；PKG使用者无需准备开发环境。

## 源码应该包含什么

保留Swift原生界面、Web公式编辑器、Node公式引擎、字体辅助程序、Word桥接与VBA源码、构建脚本、必要运行资源、可独立运行的测试、依赖锁文件和许可证。README展示精选截图，安装包通过GitHub Releases单独提供。

不收录本机Git自动检查点、REA档案、原版安装器和字体、私人Word样例、机器配置、安装好的依赖、编译缓存或历次调试输出。原始研究材料继续保留在本地。

## 独立编译的完成条件

1. 将待上传源码放入项目目录之外的全新空目录。
2. 按依赖锁文件安装Node依赖，用Swift构建App与字体辅助程序。
3. 构建不读取原工作区、REA、原版安装器或本机私有配置。
4. 在这个目录运行公开测试，再生成可启动的App。
5. Word完整安装包还需能从公开的构建说明生成加载器和原生桥，或明确提供经过验证、允许分发的构建组件。

源码使用Node、npm、Swift 6及macOS命令行开发工具是正常的开发要求；使用者下载安装包不需要这些工具。

## 两份渲染资源

两份运行资源现在随源码提供，旧版原始数据只保留在本地研究目录：

- `src/native-template-pieces.json`：三个大运算符采用随项目提供的 STIX Two Math 字形；联合标记、积分环和方向箭头由项目的参数化几何生成。
- `src/native-spacing-tables.json`：将 MathJax 3.2.2 的公开 TeX 类别间距规则映射为本引擎的正文和上下标间距表。

原版来源的字形轮廓和二进制表不再是这两个文件的构建输入。字体的 OFL、MathJax 的 Apache-2.0 和项目自绘几何的 MIT 分别保留，见根目录第三方声明。

```sh
npm ci
swift build
# 资源已随源码提供，只有重新生成时才需要执行：
node scripts/build/build-rendering-resources.mjs
npm test
./scripts/build_and_run.sh --build-only
```

替换会带来少量字形、轮廓和上下标间距差异。32组前后对照中，原生公式保存数据字节均未改变；这不等于所有公式与原版像素一致。新生成的 0.5.5 build38 安装包已包含替代资源；build37 保留为旧版参照。

2026-10-16 已将白名单源码导出到项目之外的全新目录，不补入任何私有文件，完成 `npm ci`、`swift build`、资源重建及 App 构建；两份重建资源与提交文件的 SHA-256 一致，公开测试 129 项全部通过。实际冷启动该 App，输入替代字形与环积分公式后，预览正常且原生数据检查通过。另修复了开发构建脚本在空目录首次复制引擎时的目录层级问题。

## 完整 Word 发行的额外要求

当前Word发行还使用真实Word编译并经宿主验证的冻结模板。普通用户安装完整PKG时无需手动编译；从源码重建完整发行包仍需补齐相应生成说明和输入。

Microsoft 产品图标和空公式协议样本 `src/resources/ole-template.json` 的来源问题仍单独记录于第三方声明；两份渲染资源的替换不自动解决这些项目。

## 当前安装包已确认的部分

0.5.5 build38完整PKG自带Node、引擎依赖、字体辅助程序和Word组件，默认执行Word插件安装。包解到临时目录后，在只含系统工具的PATH下，包内运行时成功完成替代运算符、联合标记和环积分的检查和渲染。

这个结果确认了所测试引擎路径的依赖完整性。当前仍缺少全新机器首次安装验收，下载信任、Word策略和特殊文档字体也需要实际确认。验收应覆盖下载、安装、打开App、Word冷启动、插入/编辑、保存及磁盘重开。
