# 图片识别公式：本轮取舍

2026-10-18：值得做成可选功能，本版先不加入模型和推理运行时。它能解决截图、论文图片里的公式重新录入的问题；已有 MathType 对象则继续走原生读取与编辑，优先保留原本的结构和设置。

建议入口是「粘贴公式图片」：保留原图，识别成 LaTeX，在现有画布中预览和修改，经过现有原生结构检查后，再由用户插入 Word。检查能判断引擎是否支持这个结构，不能证明 OCR 没有认错符号，因此不能识别后直接写进文档。

首版只考虑清晰的单个印刷公式。手写、模糊照片、多栏整页、批量转换先不承诺。模型首次使用时单独下载，显示大小、进度和移除入口；独立进程运行，闲置退出。普通用户不应再自行安装 Python 或处理推理依赖。

截至本次查阅，PaddleOCR 官方模型表中 PP-FormulaNet-S 为 224 MB，plus-S 为 248 MB，plus-M/L 为 592/698 MB；这只是模型存储，尚不包含推理运行时。当前完整 App 安装包约 80 MB，直接捆绑会明显增加每位用户的下载负担。[官方模型表](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/model_list.md)

先评估专用公式识别模型即可，不要求通用多模态大模型，也不把用户图片默认发到云端。上述模型是候选，尚未证明能在本项目的 Apple Silicon 安装包中独立运行；官方 CPU/GPU 表也不是这台 Mac 的速度或内存结果。[官方公式识别模块](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/formula_recognition.md)

进入实现前做一次有边界的小验证：固定 50 张清晰公式图片，覆盖分式、上下标、根式、积分、矩阵及易混淆符号；保留人工核对的答案。记录逐式正确率、人工修改时间、冷/热启动延迟、峰值内存、模型加运行时的安装大小，以及送入现有引擎后的支持情况。用结果决定模型与运行方式，不能用“生成合法 LaTeX”代替识别准确率。本轮未下载模型，也未运行这项基准。
